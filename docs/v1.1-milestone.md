## Known Issues Carried Into v1.1

### Profiles tab blank (P0)
**Symptom:** Preferences → Profiles tab shows an empty panel — no profile selector, no fan controls, no buttons.

**Root causes (3):**
1. `PreferencesWindowController` initializes before `prefsDelegate` is set and before fans are read from SMC. The build-time skeleton has no data source.
2. `profilesStack.widthAnchor` is constrained to `profilesScroll.widthAnchor` (the scroll view itself). `NSStackView` as `NSScrollView.documentView` must be constrained to `scrollView.contentView` (the clip view). Constraining to the scroll view produces a zero-width stack on first layout pass.
3. `refreshControls()` is called once when the window opens, never when the user actually clicks the Profiles tab. If the first call fires before layout is established, content appears blank on all subsequent views.

## v1.1 Scope

### P0 — Fix Profiles Tab
- Re-enable the Profiles tab (frozen in v1.0.x hotfix)
- Fix scroll view layout: constrain `profilesStack` to `contentView`, not `profilesScroll`
- Add `NSTabViewDelegate` — refresh content when Profiles tab becomes active
- Ensure fan config sections (mode selector, RPM slider, curve controls) render correctly

### P1 — UX Polish
- Preferences window opens to General tab by default (not Monitor)
- Profile names shown in menu bar popover with active indicator (checkmark)
- Sensible window minimum size so controls don't clip

### P2 — Backend Improvements
- Profile create/save/delete flows fully wired end-to-end
- Fan label from hardware (F{i}ID key) shown in Profiles tab headers
- Validate profile JSON on load; corrupt profiles are skipped, not crash
